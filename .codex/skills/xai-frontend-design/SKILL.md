# xAI Frontend Design

将 x.ai 的视觉系统当作一套克制的产品营销界面来实现：大留白、近黑/近白、低对比辅助文字、细分隔线、圆角胶囊和少量状态动画。目标是复刻视觉关系和交互节奏，而不是把页面内容或站点内部实现原样搬入项目。

## 使用方式

在开始编码前读取 [references/xai-style-spec.md](references/xai-style-spec.md)。其中的颜色、字体、尺寸和布局数值优先于凭感觉猜测；如果用户只要设计总结而不要代码，只输出相关章节，不修改业务文件。

当目标页面可访问时，用 `agent-browser` 在至少 1280×900 和 390×844 两个视口检查真实页面，并分别观察浅色、深色主题。当前勘察中 x.ai 真实 URL 被 Cloudflare 阻断，规格中的可渲染证据来自对应的 Wayback 快照；快照只用于视觉参考，不得写入生产链接，也不要为了绕过挑战而花费无关时间。

## 实现契约

- 先盘点现有路由、组件、主题变量和样式组织，沿用项目已有技术栈；本项目使用 React/Vite/SCSS 时，不要仅为复刻这套风格引入 Tailwind。
- 先落地全局 token，再写组件。页面中的颜色、间距、圆角、边框透明度和字号应引用 token，避免在每个组件中出现互相漂移的魔法数字。
- 桌面端使用固定顶栏、`max-width: 1280px` 的内容容器和 24px 横向内边距；移动端使用 16px 内边距。页面不要用阴影、渐变或彩色装饰填满空白区域。
- 主标题使用 Display 字体，正文和导航使用 Text 字体；找不到有授权的 Universal Sans 时使用度量接近的本地替代字体，不下载或提交未获授权的站点字体文件。
- 交互必须有完整状态：hover、focus、active、disabled、浅色/深色、移动菜单开合、导航下拉和滚动中的 feature 激活项；动画只改变透明度、亮度或高度，不使用夸张的缩放和弹跳。
- 对滚动联动优先使用 `IntersectionObserver` 或可控的 scroll progress，并在 `prefers-reduced-motion` 下关闭过渡；内容、链接和表单仍必须可键盘操作。
- 不覆盖用户已有的未提交修改。完成后只检查与本技能相关的文件和页面。

## 推荐交付流程

1. 建立 token 与字体层，先让 body、标题、链接、边框和卡片在两个主题下正确。
2. 实现共享站点壳体：logo、导航、产品/解决方案下拉、右侧 CTA、移动全屏菜单、主题切换和 footer。
3. 按页面模式实现 hero、卡片网格、sticky 演示面板、功能清单、三步卡片和 API 横幅。
4. 在 1280×900、768×900、390×844 截图复核，至少检查：标题换行、卡片顺序、顶栏覆盖、CTA 高度、分隔线位置、深色对比度和 footer 溢出。
5. 对比目标截图时先修正容器宽度、垂直节奏和字体度量，再修正颜色透明度；不要用局部负 margin 掩盖整体布局错误。

## 验收重点

- 浅色：背景为纯白，主文字近黑，卡片为暖灰白；深色：背景为 `#0A0A0A`，卡片为 `#1A1A1A`，边框为近黑蓝灰。
- 主标题在桌面约 60px/60px，在手机约 36px/39.6px；正文辅助色明显弱于主文字，但仍可读。
- 所有主按钮为 44px 高的胶囊；导航 CTA 为 36px 高。圆角、透明边框和左右间距比阴影更重要。
- Solutions 卡片在桌面为 3 列、16px 间隙；手机单列，常规卡约 240px 高，最后的虚线探索卡按内容收缩。
- Grok 功能区桌面左侧四段滚动文字、右侧 660×440 左右的 sticky 演示卡；活动段 opacity 为 1，其余约为 0.2，并用 500ms 透明度过渡。
- 最终用浏览器实际截图和可访问性树确认导航、CTA、主题切换和移动菜单，而不是只凭 DOM 是否存在判断完成。
